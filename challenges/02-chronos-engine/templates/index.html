01 / SIGNING ORACLE

Public timeline signatures

POST a JSON message that begins with timeline:. The engine returns r, s, the message digest z, and the epoch that produced the nonce. 

POST /api/sign
{"message":"timeline:snapshot-42"}

The oracle deliberately refuses to sign vault:admin.

02 / VAULT DOOR

Open the archive

The vault verifies a secp256k1 / SHA-256 signature over the exact string vault:admin. Present the signature as hex integers. 

POST /api/vault/open
{"message":"vault:admin","r":"0x...","s":"0x..."}

A valid attestation returns the archive flag.

OPERATOR NOTES

Why is audit mode deterministic?

Replaying an audit trail should produce byte-identical signatures. To make that possible, the signing nonce is derived from the engine's private nonce seed and the current epoch, rather than a fresh random value per request.
